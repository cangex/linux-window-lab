# P2 分区 UEFI 与平台描述

**结果：修复后完整的 10/10 次冷启动通过，每轮九项 EFI 自检通过。649 次 Linux fsync/读回与 TCP 样本均通过，ping 失败为零，最大 TCP 间隔 1.658 秒，内核 taint 均为零。** 首轮连续观察 300 秒，其余九轮各 30 秒。

实验日期：2026-10-13。实验对象为 `lwlab-boot`；宿主机和 `lwlab-dev` 未参与 AP 移交。完整原始日志保存在宿主机 `/data/linux-window-lab/artifacts/p2/`。

## 实现

P2 复用 P1 已验证的指定 AP 启动机制，在 CPU 4 上进入独立 EDK2 DXE core。主 Linux 继续使用 CPU 0–3；CPU 5–7 下线停驻。Linux 预留 `0x40000000..0x4fffffff` 的 256 MiB，分区只从这一范围分配内存。

引导包包含自定义 64 位入口、离线重定位的 DXE core、白名单 FV、只读 FAT 内存盘、PI HOB 和独立 ACPI 表。入口加载私有页表、GDT、IDT 和栈，通过 handoff v2 提供 generation、APIC ID、布局与 TSC 频率。HOB 将 payload、核心、FV、内存盘、ACPI、页表、mailbox、栈和 runtime 页排除出常规空闲内存。

ACPI 包含 RSDP/XSDT、MADT、FADT/DSDT、SRAT。只列出 APIC ID 4，无 PCI、IOAPIC 或 HPET。CPU 属于原 VM proximity domain 1，分区内存属于 domain 0；这与外层 QEMU 的实际 NUMA 布局一致，并未把远端内存伪装成本地内存。

COM1 归 Linux，COM2 归分区。Linux 配置同时禁用 `CONFIG_SERIAL_8250_PNP` 和设置 `8250.nr_uarts=1`；仅后者不足以阻止 ACPI/PNP 后续枚举串口。已检查 `/proc/tty/driver/serial` 只有 `0x3f8`。

## 验证方法

专用 EFI 应用从分区内存盘运行九组检查：

| 位 | 实际检查 |
| --- | --- |
| 0 | CPUID 返回 APIC ID 4，自检镜像位于分区内 |
| 1 | RSDP/ACPI 校验和、指针、MADT 单 CPU、SRAT 内存范围与 NUMA、受限 FADT |
| 2 | AllocatePages/FreePages、GetMemoryMap、越界固定地址/最大地址分配被拒绝 |
| 3 | 查找 SimpleFileSystem，打开并读取固定内容文件，拒绝文件写入 |
| 4 | LoadImage/StartImage 加载第二个 EFI 应用并检查其返回标记 |
| 5 | 创建周期定时事件，WaitForEvent 一百次，取消/关闭并检查 LAPIC tick 增长 |
| 6 | 变量写入、读取及缓冲区过小错误；变量使用 NV/BS/RT 属性，后端是模拟内存存储 |
| 7 | 错误 map key 的 ExitBootServices 被拒绝，刷新 memory map 后退出成功，收到退出事件 |
| 8 | SetVirtualAddressMap 使用 `PhysicalStart + 4 GiB`，通过转换后的函数指针读取、更新并再读取变量 |

EFI 完成后以 `checks=0x1ff stage=2 phase=9` 发布成功，再更新 mailbox 心跳。Linux 检查 generation、APIC、CR3、初始栈、magic、检查位及 tick，不将仅进入入口视为成功。

Linux 连续性测试在启动 AP 前建立 TCP 连接，在另一线程发起启动请求；每秒执行文件写入、fsync、读回校验和并通过同一连接发送结果。每轮另有 Linux 参数拒绝、重复启动/重新加载拒绝、禁止 AP 重新上线的检查。验收同时检查不同 boot ID、CPU 心跳、Linux taint 和 dmesg。

最终验收结果见同目录 `p2-validation.json`；独立复核脚本为 `p2/verify-results.py`。首轮连续观察 300 秒，其余九轮各 30 秒；这些是 P2 功能与短时稳定性验证，不代替 P3 的 Windows 30 分钟或 P6 长时间负载验收。

## 能力边界

这是独立分区中的真实 EDK2 服务验证，不恢复主 Linux 原来的 UEFI Boot Services，也不使用原固件的 runtime 上下文。尚无 Windows/WinPE 镜像接入结果。

runtime 测试保留身份映射，只验证所测服务的虚拟地址重定位与调用；不证明移除全部物理别名后的完整正确性。变量可接受 NV 属性，但目前只存于分区 RAM，冷启动不持久化。时间/唤醒明确返回不支持；ResetSystem 记录并停驻 AP，不复位整机。没有图形/交互控制台、PCI、SMM、MP Services 或通用内存保护重映射。

当前 hardware-reduced ACPI 仅供 P2 验证，Windows 对电源、控制台、启动设备与加载服务的实际依赖需在 P3 实测。无常驻监控层也意味着尚未覆盖 Windows 直接访问整机复位/共享寄存器的行为。P2 成功不构成完整 UEFI 兼容认证、Windows 并行运行或裸机性能结论。

Linux 必须带 `no_ipi_broadcast=1`，使 IPI 根据在线 CPU 集合发送，避免广播到已移交 AP。初轮矩阵在第七轮捕获 AP ISR 中的 `0xfc`（Linux CALL_FUNCTION_VECTOR）和待处理 `0x40`；主 Linux 仍正常。该失败记录保留在 `artifacts/p2/validation-final/`，修复后的完整矩阵另存 `validation-ipi-fixed/`。分区对未分配的外部中断立即报告 `failed_case=0x280+vector`；不将未知中断静默吞掉。定时自检扩大为 100 次周期事件，以覆盖约两秒的中断运行窗口。此设置不等于屏蔽所有可能的 NMI/SMI 或整机复位路径。
