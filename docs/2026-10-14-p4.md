# P4 验收：WinPE 数据的 Linux 外部读取

日期：2026-10-14（北京时间）。P4 已完成。两次独立冷启动均在同一 VM 中
运行主 Linux、单 AP WinPE 和 Linux 只读观察器。没有使用 Windows 进程
读取接口、调试接口或 QEMU RAM 读取来取得本阶段的数据样本。

接受率约 10.9%，其余绝大部分是故意停在奇数序号期间的快速拒绝。
忙轮询占约 0.955 个 Linux CPU 核。p50 延迟桶为 [128,256) ns，p95、p99
为 [4096,8192) ns；这些分位数针对所有尝试，包含快速拒绝，不代表已接受
完整页的独立延迟分布。性能数字来自外层 KVM，不推导裸机性能收益。

故障注入覆盖：50 ms 半写入停顿、错误 generation（返回 ESTALE）、
缓冲区撤销和新 epoch。另验证越界、区间末端跨界、整数溢出地址及 IOAPIC
MMIO 读取被拒绝，可写打开被拒绝。八项协议单元检查通过。

每条已接受样本均通过发布序号前后校验、页尾序号、FNV 内容校验和由
nonce/epoch/序号生成的逐字真值校验。这证明已知发布协议的读取正确性；
不证明任意 Windows 对象具备快照一致性，也不证明非合作内存释放可被检测。

两次试验使用不同 Linux boot ID 和分区 generation，内核及固件哈希相同。
原始与计算后结果见 [机器可读记录](p4-validation.json)，完整串口、TCP、
WinPE GDI 心跳和读取日志保存在服务器 `artifacts/p4/trial01` 与 `cold02`。
`metadata.json` 中继承的 Windows false 标志是未经组合验证的初始值；
最终共存判定以同目录 `coexistence.json` 的 `passed` 为准。

实现、复现步骤和协议边界见 [P4 README](../p4/README.md)。后续 P5 使用
完整 Windows 和版本化结构解析，单独验收。
