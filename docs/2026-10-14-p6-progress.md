## 固定版本 HAL 启动适配与刷写修复

用户已选择继续无常驻虚拟化路线，并允许研究固定 Windows 版本的 HAL 启动配置适配。新增 `p6/HalIpi.h`：ExitBootServices 成功之后、返回 Windows 加载器之前，只扫描分区内 RAM，以 PE machine/timestamp/SizeOfImage、PDB GUID/age 和发送路径指令特征识别唯一的内存映像。探测模式只读；执行模式要求 `HalpInterruptNoShorthand` 初值为零，写成一并读回。不匹配或多个匹配时中止分区启动。Linux 内核仍为最终 r5，没有改动 Windows 磁盘文件或指令字节，但**确实修改了 Windows 启动时的一个内核数据字节**。

这是依赖内部 HAL 标志的实验适配，不是微软支持的设置接口，也不能泛化到其他 Windows 版本。仅接受 ntoskrnl.exe SHA256 `93db70780a95192d13d04b4c3cb49c22a138063adba5c83d4855be02b645fdd0`、PDB key `953A8DE880B0818C32DA2DEC1D79C2D91`；PDB 给出 flag RVA `0xe0fc1c`。`verify-hal-image.py` 用真实 PE 映像执行固件中的同一匹配器，12 项受损头部、版本、PDB 或指令特征均被拒绝。

`hal-probe-01` 在启动现场找到唯一映像 PA `0x280200000`，flag PA `0x28100fc1c`、值零。`hal-enforce-smoke-01` 启动时写一，Windows 正常进入四核负载；60 秒外部观察取得 120/120 个有效样本，读回始终为一。40 次 QMP APIC 快照只捕获显式目标的 ICR 值，没有捕获快捷广播；快照不是全量中断轨迹，不能据此单独证明所有路径都已覆盖。短试 Linux 日志目前无未处理 IRQ，仍待独立恢复、正式矩阵和长稳验证。
