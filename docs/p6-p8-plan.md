## 起点与阶段划分

P5 已证明固定 QEMU 平台上，单 AP 完整 Windows 使用独占 NVMe，与 Linux
共存约 404 秒；两次冷启动均通过。58 个在线真值样本匹配，122 个独立样本中
43 个进入稳定真值窗口、79 个因转换或时间窗口被排除。辅助页撤销后的独立
扫描约 7.2–7.7 秒。详见 [P5 报告](2026-10-14-p5.md)。

下一轮将“持续运行”“独立恢复”“硬件迁移”“观察质量”“性能收益”分别验收。

| 阶段 | 回答的问题 | 主要交付 |

## P6：VM 内多核、长稳与生命周期

### P6.0 固定环境与实验预算

- 获取可持续使用的 Windows 镜像。P5 评估镜像显示许可证过期，不以修改
  时钟或激活绕过支撑长稳；若更换 build，重新生成 PDB profile 并跑 P5 回归。
- 记录当前 VM、backing chain、CPU/NUMA 配置、节点内存和磁盘余量。处理
  P5 出现过的宿主机局部内存压力，设定并发 VM 数量及每节点余量门限。
  压力负载只运行在实验 VM；宿主机资源不足时停止本轮并归类为环境失败。
- 将 Windows 安装基线保持关闭，正式运行使用独立克隆；保存同 build 的
  普通 KVM 对照环境。确认控制台、日志轮转和停止实验的方法。
- 冻结构建 manifest、实验矩阵和判定规则；试跑与正式数据分开。允许试跑
  校准阈值，正式失败后调整规则必须开启新版本试验并保留旧结果。

出口：镜像/profile 匹配、单核 P5 回归通过、资源预算与恢复点齐全。

### P6.1 Windows 多核启动

1. 为 APIC 4–7 建立显式 CPU 归属、状态和栈/启动区域；Linux 保留 0–3。
   ACPI MADT/SRAT、引导入口和可用内存由同一清单生成。
2. 实现 Windows 启动 CPU 对其他分区 AP 的初始化路径，观察 INIT/SIPI、
   IPI、TLB shootdown 与每 CPU 定时器。核查 Windows 发起的广播是否影响
   Linux，不能以 P2 修复了 Linux 的广播问题推定反向路径也已安全。
3. 验证新 AP 的实际执行和调度进展，使用逐 CPU 测试线程与负载证据；
   ACPI 列出多个处理器或界面显示数量不单独构成通过。

出口目标：1/2/4 Windows CPU 配置各 3 次冷启动与 30 分钟联合负载；固定
4 CPU 配置累计 10 次冷启动。Linux boot ID 在每轮运行中不变、I/O 校验
无错误；Windows 每个分配 CPU 都有实际负载进展。两侧越权使用 CPU 或
广播破坏另一侧属于失败，保留最小复现。

### P6.2 观察质量与真值改进

- 把内核发现、对象遍历、页表翻译和读取分别计时、计字节、计重试，避免
  将启动时扫描成本混入稳态采样成本。
- 每个样本记录 Linux 单调时钟的读取起止时间。验证器使用独立真值记录的
  事件序号/时间区间及校准误差，替代仅用遍历结束时间对齐两个系统时钟。
  真值或同步信息只供验证器使用，不传递定位地址给独立观察器。
- 保留“从未开启辅助页”的正式模式；测试应用只记录真值，Linux 新进程
  必须独立发现内核及选定对象。另保留合作真值模式用于定位错误。
- 扩展 PID/地址复用、进程频繁退出、DLL 频繁装卸、分页压力、未知 profile、
  页表/链表变化等测试。稳定快照与变化窗口分开报告。
- 不支持的页面/版本明确返回 unavailable/unsupported；过期结果携带状态，
  不沿用旧对象内容冒充新采样。

出口目标：至少 1,000 个经过独立真值核对的稳定样本，至少 100 次进程生命周期
与 100 次 DLL 装卸；稳定样本误解析为 0。正式报告必须包含全部请求、有效
输出、已核对、排除、不可用和错误的数量，以及发现/撤销延迟分布。
在预先定义的稳定驻留测试负载上，真值核对覆盖目标 ≥80% 的采样请求；
达不到时继续改进或明确标为未达标，不仅发布正确率。

### P6.3 长时间联合负载

先 2 小时，再进行 24 小时固定配置试验。负载包含 Windows CPU/内存压力、
独占 NVMe 写入/flush/读回、进程/DLL 生命周期，以及 Linux 网络与文件 I/O。
分别运行观察关闭和开启的检查，确保观察器本身的影响可辨认。

出口目标：双系统持续进展、无非预期复位、数据校验无错误、无新增内核异常。
外部读取身份/generation 不混淆。持续记录工作负载速率、内存、最大心跳间隙
与 tail latency；只证明 ping 可达不够。宿主机调度/内存干扰单独归因，受影响
轮次保留但不能顶替完整 24 小时通过记录。

### P6.4 故障与分区恢复

先观测行为，再实现状态机：

`running → stop-requested → quiescing → stopped → reinitializing → running`

任一静止条件无法确认进入 `failed-retained`：保留 CPU/RAM/设备归属，禁止
重用相关内存。每步有超时、错误码、generation 和证据；超时不算已经停机。

| 场景 | 首先验证什么 | 恢复目标 |
| --- | --- | --- |
| 测试进程退出/观察器退出 | 系统仍运行，旧对象或读句柄不会误用 | 无系统重启的重新发现 |
| Windows 受控 bugcheck | Linux 连续性、AP/设备状态及最后日志 | 独立诊断，确认可否静止分区 |
| Windows shutdown/reboot | EFI、ACPI、芯片组及设备路径的实际影响 | Linux 不停机的停止/重建 |
| NVMe 超时/复位 | 中断、队列、DMA、控制器复位影响范围 | 只恢复所属设备并重建启动状态 |
| 观察期间重建分区 | 读操作与撤销同步、旧 fd/profile/cache 失效 | 旧请求拒绝，新 generation 可重新定位 |

重建前必须确认所有 Windows CPU 停止写入、设备 DMA/中断已静止，再重新
准备固件与内存。永久预留分区内存是第一版选择，返还 Linux 分配器留待后续。
暂停 CPU 不等于设备停止 DMA，也不构成完整快照。

出口目标：每类受控故障至少 5 次；Windows 独立重启连续 10 次，Linux boot ID
不变、网络/存储负载继续、Windows boot 标识及分区 generation 更新，旧句柄
拒绝。关机、崩溃后重建分别给结果。若需 Windows 合作驱动或最小虚拟化才能
完成，明确依赖并保留路线名称；不将其混入无合作/无监控层的结果。

阶段状态分为“稳定共存通过”和“独立恢复通过”。后者未达标时，P6 整体仍
注明未完成；P7 可依据前者先迁移，并继承生命周期限制。

## P7：固定硬件上的裸机共存与外部观察

目标：在一台指定 x86-64 实验机上，让 Linux 持续运行，启动固定版本 Windows，
完成 1→2→4 个物理核的共存与外部读取，并单独验证本机的 Windows 分区恢复。
本轮以短试、重复启动和 30 分钟联合负载验收，不安排 2／24 小时长稳。
不开展通用硬件兼容、动态资源返还、第二 Windows build 或性能收益承诺。

### P7.0 冻结输入与实机清单

保留 P6 两项有效基线：`hal-mp4-30m-01` 的 3033 个稳定匹配、84.27% 覆盖、
零已核对不匹配、无异常 IRQ；`hal-recovery-single-01` 的同一 Linux boot ID 下
Windows 重启及冷盘真值核对。P6 原始失败结果不改写，其他未完成项不自动升级。

固定现有 Windows 26100.1742 内核、PE/PDB 身份和 HAL 适配条件。当前方案修改
启动时的内部 `HalpInterruptNoShorthand` 数据字节，必须作为明确的版本依赖。
WinPE 若使用不同内核，须独立生成和验证 profile，不能套用该 HAL 偏移。

确定专用机器或明确的整机实验窗口、BMC/串口或等效恢复手段、Linux 启动盘、
Windows 独占 NVMe 控制器。现有服务器的 VM 授权不扩展为裸机重启或硬件移交。
没有实机时可以完成代码抽象与 QEMU 回归，但不能把它们记作实机完成。

产物 `platforms/<machine>/`：CPU/SMT/APIC/NUMA、物理地址宽度、RAM/e820/EFI
内存图、ACPI 原表与固件版本、PCI segment/root/ECAM/BAR/桥窗口、设备驱动、
IOMMU 与中断重映射状态、DMA 路径、复位影响范围、控制台、救援启动配置。
IOMMU group 与复位影响范围分别核查。初版按完整物理核划分 SMT 同胞，静态预留
Windows RAM；整个 NVMe 控制器独占，不以分出 namespace 代替控制器归属。

出口：清单完整、资源分配无重叠、实机范围与恢复方法明确，未知项逐项列出。

### P7.1 平台清单与启动前校验

建立统一 schema 和生成器，让 Linux loader、UEFI、ACPI、观察器、恢复器消费
同一配置。保留 QEMU profile，禁止仅全局替换十六进制常量。

具体改动：
- `p6/recovery.inc`：拆开 Linux CPU 编号与 APIC ID，按清单生成 CPU 集合和确认槽，
  支持非连续 ID、1/2/4 核及实际 xAPIC/x2APIC 模式。
- `p6/HalIpi.h`：扫描区间来自经过验证的 Windows 内存清单；保留精确映像匹配、
  唯一目标、初值检查和失败即中止，不能扩大到任意物理地址扫描。
- `p5/observer.py` 与内核读取 ABI：移除恰好四段内存的假设，带版本地扩展描述符，
  按真实物理地址宽度检查范围，跨代拒绝和只读行为保持可验证。
- `p5/platform.json`、NVMe DXE、`recover.py`：移除固定 BDF、QEMU 设备 ID、BAR、
  ECAM 和四核假设，改为明确的平台/设备配置与能力检查。
- 根据实际内存图选择并预留低地址 trampoline/停驻页，不沿用固定 0x6f000。

出口：QEMU 上用非连续 APIC ID、不同可用内存段和设备位置执行功能回归；
重叠资源、错误设备、未知 Windows 身份、失效 generation 必须被拒绝。

### P7.2 CPU、内存与中断的实机最小验证

先移交单个 AP 执行最小 payload，再增加到 2/4 核，不启动 Windows。
确认 Linux 热拔 CPU 后实际目标、INIT/SIPI、独立栈、页表、缓存属性、TSC/定时器，
以及每核停止确认。RAM 在启动时预留，不动态从业务内存中挤出。

分析两侧 LAPIC、IOAPIC、MSI/MSI-X、中断重映射和固件状态的职责。IOMMU 若需要，
用于 DMA 路径与设备兼容，不据此增加跨系统读取保密验收目标；不能整机关闭它
来绕过未知问题。全局状态不能由两个内核各自任意重置。

出口：每个目标 AP 有实际执行与停驻证据，Linux 网络/存储连续、boot ID 不变，
无异常中断、内存覆盖或超时。失败则停留在最小 payload 层定位。

### P7.3 分区 UEFI、ACPI 与真实 NVMe

构建与实际分区一致的 MADT/SRAT/MCFG/DSDT/FADT 等表，按平台需要选择和验证，
不照搬整机 AML 或假定 QEMU 的 hardware-reduced ACPI 可直接用于实机。
Windows 会解释 ACPI AML 并据此管理硬件，必须核查方法涉及的 I/O/MMIO 和共享
状态：[微软 ACPI 表说明](https://learn.microsoft.com/en-us/windows-hardware/drivers/bringup/acpi-system-description-tables)。

移交 NVMe 前确认驱动释放、队列/中断/DMA 静止；实现真实设备识别、BAR/DMA
地址检查、控制器复位及超时保留。核查 PCI 根桥配置、MSI/MSI-X 与实际 IOMMU
映射关系。Linux 与 Windows 各自的启动设备不得处于未经确认的共同复位范围。

出口：分区 UEFI 分配、加载、ExitBootServices 自检通过；独占测试盘读写/flush/
读回正确，Linux 设备不受影响，失败时不归还尚未静止的资源。

### P7.4 Windows 启动与 HAL 适配实机验证

按“引导环境/WinPE → 固定完整 Windows → 1/2/4 核”逐级推进；每步先有用户态
和实际负载证据，再扩大 CPU 数。HAL 适配每次引导都核验并外部读回，未知版本
中止；QEMU 中未观察到广播不能代替实机 IRQ/IPI 检查。

第一版采用串口与内存 GOP 等已明确的控制台方式，不把 GPU、音频、USB 共享
加入首个闭环。固件服务、SMM、芯片组电源/复位路径作为实机待测依赖记录。

出口：Windows 启动驱动与用户态运行，各分配 CPU 实际推进，Linux 持续服务，
没有未经协调的跨分区中断或设备操作。

### P7.5 外部观察与短负载验收

复用 `/dev/lwobserve` 路径，从 Linux 独立发现内核、进程和模块；不能依赖 QMP
物理内存访问或 Windows 提供目标地址。真值只写 Windows 独占盘，关停后核对。

建议冻结以下本轮验收矩阵：
- 1/2/4 核各 3 次冷启动，每次至少 5 分钟 CPU/内存/I/O 短试。
- 固定四核再做一轮 30 分钟联合负载与外部观察。
- 至少 1000 个稳定真值样本，覆盖率至少 80%，零已核对误解析；分别报告排除、
  不可用和错误，提供 p50/p95/p99。不把采样延迟声称为应用性能收益。
- 单独运行至少 100 次进程创建/退出及 DLL 装卸测试，补足 P6 尚未完成的事件数量。
- 所有轮次核查 Linux boot ID、网络/存储校验、逐 Windows CPU 进展及异常日志。

出口：明确标记“指定裸机的短时共存与观察通过”；不宣称长稳或跨硬件兼容。

### P7.6 本机独立恢复与交付

先做主动 stop/prepare/start；核对全部 CPU 停驻、NVMe DMA/中断静止、旧 fd 与
旧 generation 拒绝。确认同一 Linux boot ID 下新 Windows BootId、workload 身份和
generation 更新，并从冷盘验证新实例真值。失败进入 failed-retained，不重用 RAM。

单次通过后连续执行 3 次；再分别探索 Windows shutdown、reboot、bugcheck 与
设备超时，按影响范围逐项推进。短试数量不替代原 P6 的完整故障矩阵，未测场景
不列为支持。需要整机复位恢复的情况作为失败保存，不计 Windows 独立恢复。

产物：平台清单及生成器、适配代码、冻结版本/哈希、启动与恢复脚本、原始日志
索引、验收汇总、救援和回滚手册。共存观察与分区恢复分别给出状态；后者未通过
时不能宣称完整 P7 生命周期能力。完整重建应只用合法持有的 Windows 输入。

### 执行顺序与当前可开展工作

顺序：P7.0/P7.1 → P7.2 → P7.3 → P7.4 → P7.5 → P7.6。
目前可先完成 schema、校验器、CPU/APIC 映射、内存描述符和 QEMU 回归；实机执行
依赖测试机器清单与专用范围。不恢复旧长稳批次，不把规划请求视作已授权操作
当前业务宿主机的启动配置。设备复位和固件适配完成前，不承诺固定总工期。

## P8：观察系统完善与最终评估

### P8.1 可使用的只读观察接口

首个接口范围：列举进程、列举内核模块、列举目标原生 x64 进程模块、翻译
指定 VA、读取指定进程的有界 VA 区间。使用 `(generation, PID, CreateTime,
EPROCESS)` 对象句柄，防止 PID 复用；输出 profile 身份、起止时间、状态和
不可用原因。Linux 本地工具/API 先行，暂不建设远程控制平面或网页产品。

演示任务固定为观察一个受控应用的进程和 DLL 变化，读取其带序号的目标
缓冲区，应用退出后拒绝旧句柄。明确外部读取不经过 Windows 对象访问接口；
可选用无读取权限的普通 Windows 账户做对照，实际目标数据仍为自有测试数据。

### P8.2 版本与读取成本

支持至少两个固定 Windows build：各自冻结介质、PE/PDB 身份、profile、
引导和观察结果。未知/错误 profile 必须拒绝解析。第二 build 的通过条件
包含实际共存启动，不能只生成偏移文件。

在 P6 数据基础上优先优化重复扫描、过碎 ioctl、批量页读取和重复对象遍历。
任何缓存均明确 generation/对象身份与失效条件，并用进程复用、页表变化和
分区重启回归。分别报告冷发现、重发现、稳态采样、页表翻译和内容读取成本。
首个交付仍不包含任意分页文件恢复、全文件系统解释或任意跨对象原子快照。

### P8.3 公平对照与结论

| 路线 | 作用 |
| --- | --- |
| Windows 裸机独占 | 硬件与 Windows 工作负载基准，记录 CPU/内存限制及差异 |
| Linux + 优化 KVM Windows | 专用 CPU、匹配 NUMA/内存、可用时同设备直通；同时保留相同 Linux 负载 |
| Linux–Windows 裸机分区共存 | 本项目主结果，同资源与工作负载；观察关闭/开启/多种频率 |
| 最小虚拟化静态分区（若实际实现） | 独立路线，单独报告常驻职责及恢复/成本差异 |

匹配 Windows build、CPU/SMT、可用 RAM、设备、频率/电源策略、负载和运行
时段，记录无法匹配的项目。普通 KVM 使用匹配的解析工作与采样频率做读取
对照，并说明后端差异。P5 外层 QEMU 内共存只作功能回归。

测量 Windows/Linux 吞吐、p50/p95/p99 延迟与抖动、观察开启造成的工作负载
变化、观察 CPU/内存/物理读取量、有效语义样本速率、真值覆盖率和检测延迟，
以及启动/恢复时间。P4 重复读取页的字节吞吐不作为新数据速率。

先试跑确认预热与稳态区间，再冻结正式配置；主要性能点至少 5 次独立运行，
报告各次值、区间和失败轮次，尾延迟附样本量与采样方法。长稳另外报告。
性能改进没有预设百分比：正确性通过且比较完整，负收益也作为有效结论保留。

### P8.4 交付与发布

从干净环境按文档完成一次独立重建/部署/验证。保存构建与平台 manifest、
测试命令、原始证据索引和校验和、结果汇总、分析脚本、支持矩阵与恢复手册。
不分发 Windows 系统镜像、凭据或有许可证限制的构建输入。

出口：两 build 回归通过、未知版本拒绝、选定应用演示可复现、公平对照与
数据完整。发布说明明确平台、CPU 数量、设备、版本、恢复能力和观测限制。

## 优先级与检查点（2026-10-16 修订）

1. 归档 P6 有效短试与失败证据，2／24 小时长稳取消本轮执行；不恢复旧批次。
2. 先开发 P7.0/P7.1 的清单、校验器和 QEMU 回归，落实专用裸机及恢复条件。
3. 实机按 AP payload → 分区 UEFI/设备 → Windows → 多核观察推进，每级实测通过后扩大范围。
4. 裸机独立恢复单列，P6 的 VM 结果不能直接继承为实机能力。
5. P8 的 API 和普通 KVM 对照准备可独立推进，性能结论等待实机结果。

每个工作包交付代码、冻结配置、原始证据和通过/失败结论。未运行项不记为通过；
当前业务宿主机的裸机测试范围尚未落实，规划不改变原来的 VM 操作边界。
